# Tool workflow

This is an observation aid for the explicitly invoked research skill. It is
not executable quota enforcement and contains no key or fixed vendor schema.

## Before a request

Record the approved public question and destinations, explicit budget, and
relevant tool name exactly as advertised by the connected account. Validate
inputs against that tool's current schema. An available tool is not itself
authorization to call it.

## Observation table

| Item | Record | Avoid |
| --- | --- | --- |
| Calls | Each observed research, polling or retry call | Claiming a hard server cap from prompt instructions |
| Evidence | Returned URL, passage and date when present | Invented citations or inferred dates |
| Jobs | Actual advertised status and task identifier | Promising local cancellation stopped remote billing |
| Errors | Redacted category and unfinished work | Raw headers, keys or credential-bearing error strings |

## Stop decisions

Stop before another call when the budget is exhausted or unclear. Authentication,
permission, credit and quota errors require an account/configuration action;
do not probe alternative credentials. An empty result may be a legitimate
no-result outcome and should be reported as such.

## Synthetic example

A user allows four tool calls. One lookup is observed and produces two public
source URLs; one supplied source has no date. Report one observed call, link
the returned sources, mark the date unknown, and avoid saying all three sources
were independently verified. This example is illustrative, not live evidence.
